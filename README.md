# pii-check

チェックデジットや固定ルールで**機械的に検証できる識別子**の検証部品（Python、標準ライブラリのみ）。
「この文字列はマイナンバーとして正しい形式か」を、毎回作り直したり LLM に聞いたりせずに判定するためのものです。

ファイル単位で使いたい場合は `pii_scan.py`（後述）：CSV / JSON Lines / JSON 配列をカラムごとに走査して「このカラムに PII があるか」を報告します。GB〜TB 級を想定し、ストリーミング処理＋デフォルトで先頭10万件のサンプリングです。実測では 20万行（3カラム）の全件スキャンが約2.6秒（このマシンの共有 CPU で約7.7万行/秒）。TB 級の全件は現実的でないので、まずサンプリングで当たりを付ける使い方を想定しています。

```sh
python3 pii_scan.py data.csv                 # 要約を標準出力へ
python3 pii_scan.py data.jsonl --full --json-out report.json
```

## 使い方

```python
from pii_check import is_my_number, is_corporate_number, is_credit_card, is_imei, classify

is_my_number("407925273108")        # True（検査用数字が正しい）
is_corporate_number("8459565131062") # True
is_credit_card("4242-4242-4242-4242") # True（Luhn通過。区切り文字は除去されます）
classify("042675612697051")          # ['credit_card', 'imei'] のように該当するものをすべて返す
```

## 対象と検証方法

| 関数 | 対象 | 検証 |
|---|---|---|
| `is_my_number` | 個人番号（マイナンバー、12桁） | 検査用数字（省令の式） |
| `is_corporate_number` | 法人番号（13桁） | 検査用数字（国税庁の式） |
| `is_credit_card` | カード番号（13–19桁） | Luhn（ブランド判定はしません） |
| `is_imei` | IMEI（15桁） | Luhn |
| `is_drivers_license` | 運転免許証番号（12桁） | 11桁目のチェックデジット（モジュラス11・ウェイト2〜7） |
| `is_jp_phone_number` | 日本の電話番号（10–11桁） | **形式のみ**（チェックデジットなし。番号計画の大枠：携帯/IP の11桁帯域、市外局番等の10桁。個別の市外局番の実在までは照合しません） |

## 設計上の割り切り

- 判定は「形式と検査用数字が正しい」ことだけを意味します。その番号が実在するか、誰のものかは分かりません（それがこの部品の意図です：機械的に分かることだけを機械で判定する）。
- `classify` は排他ではありません。たとえば15桁の IMEI はカード番号の桁数・Luhn 条件も満たすため、両方が返ることがあります。
- チェックデジットのない識別子（電話番号など）は対象外です。形式だけで「らしい」と判定するヒューリスティクスは入れていません。
- 文字列でない入力や、数字以外の文字（全角数字を含む）には例外を投げず False を返します。

## テスト

```sh
python3 test_pii_check.py
```

テストベクトルは公開された検査用数字の式から生成したものと、公開テスト用カード番号を使っています（実在の番号は含みません）。
