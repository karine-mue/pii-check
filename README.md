# pii-check

チェックデジットや固定ルールで**機械的に検証できる識別子**の検証部品（Python、標準ライブラリのみ）。
「この文字列はマイナンバーとして正しい形式か」を、毎回作り直したり LLM に聞いたりせずに判定するためのものです。

構成は2つです。

- `pii_check.py` — 値ひとつを判定する検証関数群
- `pii_scan.py` — ファイルをカラム単位で走査し「このカラムに PII があるか」を報告するスキャナ

## 使い方（目的別）

### 単体実行：値ひとつが正しい形式か確かめる

```python
from pii_check import is_my_number, is_corporate_number, is_credit_card, classify

is_my_number("407925273107")          # True（検査用数字が正しい）
is_corporate_number("2407925273103")  # True
is_credit_card("4242-4242-4242-4242") # True（Luhn 通過。区切り文字は除去されます）
classify("042675612697051")           # ['credit_card', 'imei'] のように該当するものをすべて返す
```

### 一括実行：ファイルのカラムに PII があるか調べる

CSV / JSON Lines / JSON 配列に対応します。GB〜TB 級を想定し、ファイルを丸ごとメモリに載せないストリーミング処理です。

```sh
python3 pii_scan.py data.csv                                  # 先頭10万件をサンプリングして要約を表示
python3 pii_scan.py data.jsonl --full --json-out report.json  # 全件走査してレポート JSON も書く
python3 pii_scan.py data.json --sample 1000                   # JSON 配列を先頭1000件だけ
```

出力はカラムごとに `verdict`（pii / possible / none）、最頻の種別、一致率、マスク済みの実例です。ライブラリとして使う場合は `scan_csv` / `scan_jsonl` / `scan_json_array` / `scan_file` がレポート dict を返します。

## 対象と検証方法

| 関数 | 対象 | 検証 |
|---|---|---|
| `is_my_number` | 個人番号（マイナンバー、12桁） | 検査用数字（省令の式） |
| `is_corporate_number` | 法人番号（13桁） | 検査用数字（国税庁の式） |
| `is_credit_card` | カード番号（13–19桁） | Luhn（ブランド判定はしません） |
| `is_imei` | IMEI（15桁） | Luhn |
| `is_drivers_license` | 運転免許証番号（12桁） | 11桁目のチェックデジット（モジュラス11・ウェイト2〜7） |
| `is_jp_phone_number` | 日本の電話番号（10–11桁） | **形式のみ**（チェックデジットなし。番号計画の大枠で判定） |

## テストと検証結果

```sh
python3 test_pii_check.py   # 検証関数のテスト
python3 test_pii_scan.py    # スキャナのテスト（20万行の全件スキャンを含む）
```

検証の方法と結果は次のとおりです（2026-11-15 実施、全項目パス）。

- テストベクトルは、公開された検査用数字の式から生成した合成値と、公開テスト用カード番号を使用（実在の個人番号・法人番号はベクトルに含めていません）。
- 法人番号の式は、実在の公開法人番号（法人番号公表サイトで確認できるもの）でも照合し、検査用数字が一致することを確認しました。
- 個人番号の式は省令の原文、運転免許証の式は警察庁の形式文書に基づく資料で確認しました。
- スキャナは 20万行（3カラム）の CSV 全件スキャンが約2.6秒（共有 CPU のマシンで約7.7万行/秒）でした。TB 級の全件走査は現実的でないため、サンプリングで当たりを付ける使い方を想定しています。
- スキャナのテストには、1要素が読み込みチャンク（64K文字）より大きい JSON 配列のケースも含みます。

## 注記

- 判定が通ることは「形式と検査用数字が正しい」ことだけを意味します。その番号が実在するか、誰のものかは分かりません（機械的に分かることだけを機械で判定する、がこの部品の意図です）。
- `classify` は排他ではありません。たとえば15桁の IMEI はカード番号の桁数・Luhn 条件も満たすため、両方が返ることがあります。
- 電話番号にはチェックデジットがないため、形式ティアとして分離しています。番号計画の大枠（携帯・IP電話の11桁帯域、市外局番等の10桁）で判定し、個別の市外局番の実在までは照合しません。スキャナでも形式ティアの一致は `possible` 止まりで、`pii` とは判定しません。
- 健康保険証番号と生年月日は対象外です。保険証番号は保険者ごとに形式が異なり全国統一の検査用数字がなく、生年月日は「実在する日付か」は判定できても「生年月日であること」は形式から区別できないためです。
- 文字列でない入力や、数字以外の文字（全角数字を含む）には例外を投げず False を返します。
- スキャナの判定はセル値全体に対して行います。自由文の中に埋め込まれた番号の抽出（部分文字列検索）は行いません。
- スキャナのレポートに残る実例はマスク済みです（先頭2文字と末尾2文字のみ）。生の値はレポートに書きません。
